# Autonomous official-source cataloger

The hourly worker researches missing grant fields without paid search or AI. It uses the existing approved sources, safe reader, robots rules, PostgreSQL lease, and bounded GitHub Actions runtime. Maintenance receives the first 50% of pages/time, enrichment and reconciliation 30%, and searches/discovery the remainder. Spare time and pages transfer; per-source and aggregate limits span all phases. These are capacity targets, not freshness guarantees.

Migration 020 adds resumable research pages/jobs, field states, locks, and append-only application-level field history. Apply it before deploying the application or worker, then rerun `db/operations/discovery-role.sql` and grant the existing app role access to the four new tables. Grant the backup role SELECT. Do not grant the worker account/private-application access.

Recognizable published programs get one enrichment job each. New source evidence or an extractor version change wakes the job; otherwise completed/incomplete research repeats weekly. Approved program, guidelines, application, FAQ, feed/sitemap and PDF links are prioritized by missing fields, with at most ten supporting pages plus the program page. Download failures retain checkpoints and retry with exponential backoff. Recent evidence can be reprocessed without downloads. All network calls use the protected reader. No browser rendering or OCR service is introduced: inaccessible/scanned-only documents remain unresolved.

Evidence records retain excerpts, URLs, fetch dates, and labeled funding rounds. Calendar year equality is not required: cross-year and future funding rounds may be usable when their explicit application evidence supports them. Historical-only material, conflicting current statements, and incidental eligibility mentions do not become current search facts. Supported application status, date, USD amounts, rolling intake, applicant types, and geography update catalog fields; omitted facts do not erase known values. Current contradictions become Unknown and retain their prior history. Only explicitly supported applicant/location values enter precise filters.

An old human-verification flag no longer prevents supported updates. Automatic edits clear that human-verification claim, retain the previous value in history, and respect explicit field locks. The admin Catalog tab offers lock/unlock and restore-previous-value; restore also locks the field. These operations require verified editor access and run transactionally. Saves, application IDs, notes, tasks, and application histories are untouched. Hidden/merged/archived records stay excluded.

Overview shows per-field completeness and research/retry/unavailable counts. Research progress explains unfinished checks. Admin exceptions covers new domains, locked conflicts, and persistent source failures; missing data is not an approval task. Publication triage dismisses confirmed non-program candidates and retries skipped extraction when the parser changes. Uncertain identity remains separate, never merged by title alone.

Release: encrypted backup and baseline completeness counts; apply migration/role grants; pass tests and production build; deploy app and main-branch worker; manually dispatch Catalog discovery and maintenance using the existing 840-second bounded option. Compare per-field counts and inspect changed official excerpts. Keep the hourly cron unchanged. Failure rollback uses the prior app release with additive tables retained; individual fact rollback is available in the admin. Never claim full coverage from a bounded pass.
